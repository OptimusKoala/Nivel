# Nivel 1.15 — Lot C : Sport — Plan d'implémentation

> **Pour les agents :** SOUS-COMPÉTENCE REQUISE — utiliser `superpowers:subagent-driven-development` (recommandé) ou `superpowers:executing-plans` pour exécuter ce plan tâche par tâche.

**But :** deux activités de plus (piscine, ping-pong), et un filtre « Dehors » qui cesse de mentir.

## ⚠️ Trois choses à savoir avant de commencer

**1. Le ménage existe déjà.** `active_cleaning`, « Ménage actif », à la maison, 3,5 kcal/min, depuis la v1. La demande initiale le citait ; la vérification a montré qu'il était là. **Ne rien ajouter de ce côté** — décision explicite de Michaël, pas un oubli de ce plan.

**2. Aucune illustration, aucun build.** `scripts/import-sport-images.sh` compare les ids de **tous** les catalogues aux fichiers de `design/sport/` et **s'arrête en erreur** si un seul manque (`diff` sur les listes triées, ligne 22). Les deux nouvelles activités exigent donc leurs deux PNG sources avant que quoi que ce soit ne compile avec les assets à jour. Ce plan est écrit pour que les Tasks 1 et 2 restent faisables **sans** les images ; seule la Task 3 les demande.

**3. Pas de tiret cadratin dans les JSON.** `testNoBundleResourceContainsEmDash` balaie **toutes** les ressources du bundle. Les `instructions` des deux activités doivent s'écrire à la virgule ou aux deux-points. Cette règle vient de la v1.2 et n'a jamais été assouplie.

```swift
/// Les deux activités de la 1.15 §5.1, transcrites depuis la table de la spec.
/// Garde-fou de transcription : ces nombres viennent d'un tableau, et un tableau
/// se recopie mal.
func testLesDeuxActivitesDeLaMaisonDesAmisSontPresentes() throws {
    let parID = Dictionary(uniqueKeysWithValues: try Catalogs.activities().map { ($0.id, $0) })

    let piscine = try XCTUnwrap(parID["swimming"])
    XCTAssertEqual(piscine.name, "Piscine")
    XCTAssertEqual(piscine.kcalPerMin, 7.0)
    XCTAssertEqual(piscine.durations, [15, 30, 45])

    let pingPong = try XCTUnwrap(parID["table_tennis"])
    XCTAssertEqual(pingPong.name, "Ping-pong")
    XCTAssertEqual(pingPong.kcalPerMin, 4.5)
    XCTAssertEqual(pingPong.durations, [15, 30, 45])

/// Ni chez soi, ni dehors : c'est le sens de `both`, et c'est ce qui motive le
/// changement de filtre de la Task 2. Aucune des deux ne produit de pas comptés
/// par HealthKit, donc `stepsBased` reste faux : sans quoi l'anneau de dépense
/// les défalquerait comme il le fait pour la marche.
func testLesDeuxNouvellesActivitesSontMixtesEtSansPas() throws {
    for id in ["swimming", "table_tennis"] {
        let activite = try XCTUnwrap(try Catalogs.activities().first { $0.id == id })
        XCTAssertEqual(activite.location, .both, id)
        XCTAssertEqual(activite.intensity, .gentle, id)
        XCTAssertFalse(activite.stepsBased, id)
        XCTAssertGreaterThanOrEqual(activite.instructions.count, 3, id)
    }
}

/// Le ménage était dans la demande d'origine. Il existait déjà. Ce test empêche
/// qu'un doublon bien intentionné n'apparaisse un jour.
func testLeMenageNExistePasEnDoubleExemplaire() throws {

    XCTAssertEqual(menages.map(\.id), ["active_cleaning"])
}

func testLeCatalogueCompteTrenteDeuxActivites() throws {

}
```

## Task 2 : « Dehors » cesse d'exclure les activités mixtes

**Fichiers :**
- Modifier : `NivelCore/Sources/NivelCore/ActivityCatalog.swift:123`
- Test : `NivelCore/Tests/NivelCoreTests/ActivityCatalogTests.swift`

**Le défaut, en une phrase :** `gentleHome` prend `location != .outdoor` (donc `home` **et** `both`) tandis que `gentleOutdoor` prend `location == .outdoor` (donc `outdoor` **seulement**). Une activité `both` n'apparaît par conséquent que dans « Chez soi ». C'est déjà faux pour `stairs` depuis la v1, et ce serait faux pour la piscine et le ping-pong.

- [ ] **Étape 1 : écrire les tests qui échouent**

```swift
/// `both` veut dire « les deux » (spec 1.15 §5.2). Avant ce changement,
/// `gentleOutdoor` filtrait sur `== .outdoor` et n'en montrait aucune.
func testUneActiviteMixteApparaitDansLesDeuxSections() throws {
    let catalogue = try Catalogs.activities()
    let chezSoi = Set(ActivityCatalog.section(.gentleHome, from: catalogue).map(\.id))
    let dehors  = Set(ActivityCatalog.section(.gentleOutdoor, from: catalogue).map(\.id))

    for id in ["swimming", "table_tennis", "stairs"] {
        XCTAssertTrue(chezSoi.contains(id), "\(id) absente de Chez soi")
        XCTAssertTrue(dehors.contains(id), "\(id) absente de Dehors")
    }
}

/// La contrepartie, pour que le filtre ne devienne pas « tout, partout » : une
/// activité strictement à la maison ne doit JAMAIS apparaître dans Dehors.
func testUneActiviteDeMaisonNApparaitJamaisDehors() throws {
    let catalogue = try Catalogs.activities()
    let dehors = ActivityCatalog.section(.gentleOutdoor, from: catalogue)
    XCTAssertTrue(dehors.allSatisfy { $0.location != .home })
    XCTAssertFalse(dehors.contains { $0.id == "squats" })
}

/// Les activités intenses ne bougent pas : leur section ignore `location`.
func testLaSectionIntenseNEstPasTouchee() throws {
    let catalogue = try Catalogs.activities()
    let intenses = ActivityCatalog.section(.strong, from: catalogue)
    XCTAssertEqual(intenses.count, 10)
}
```

- [ ] **Étape 3 : changer le filtre**

Dans `ActivityCatalog.swift`, ligne 123 :

```swift
        // `!= .home` et non `== .outdoor` (spec 1.15 §5.2) : une activité `both` se

```
