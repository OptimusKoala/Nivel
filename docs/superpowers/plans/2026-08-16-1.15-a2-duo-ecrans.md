# Nivel 1.15 — Lot A2 : le duo, appairage et écrans — Plan d'implémentation

> **Pour les agents :** SOUS-COMPÉTENCE REQUISE — utiliser `superpowers:subagent-driven-development` (recommandé) ou `superpowers:executing-plans` pour exécuter ce plan tâche par tâche.

**But :** appairer deux iPhones par QR code, recevoir un cœur, et montrer la journée de l'autre.

**Architecture :** `DuoService` est le seul objet observable de la feature ; il s'appuie sur `DuoIdentity`, `DuoDatabase` et `DuoPublisher` posés au lot A1. Les écrans ne parlent jamais à CloudKit directement. La règle du dépôt s'applique telle quelle : toute décision qui peut se prendre sans écran vit dans NivelCore et est testée, le reste est de la vue.

**Pile :** SwiftUI, CloudKit, `CIFilter.qrCodeGenerator`, `DataScannerViewController`, `UNUserNotificationCenter`.

**Spec :** `docs/superpowers/specs/2026-08-16-nivel-1.15-design.md` §3.6 à §3.11.

**Dépendance : le lot A1 en entier.** Ne pas commencer avant qu'il soit vert.

---

## ⚠️ Six choses à savoir avant de commencer

**1. `xcodegen generate` après chaque fichier créé.** Ce plan en crée neuf.

**2. Rien de ce lot ne se teste en intégration.** Ni le simulateur ni la CI ne savent jouer deux comptes iCloud. Les tests portent sur les décisions **pures** extraites des vues ; l'appairage et le push se vérifient à la main sur deux iPhones, et la liste de cette vérification est en fin de plan. Ne pas écrire de test qui touche un vrai conteneur CloudKit.

**3. Aucune erreur de duo ne doit interrompre l'utilisateur.** La publication est fire-and-forget depuis le lot A1. Côté écrans, un échec se raconte dans la ligne de fraîcheur ou dans la section Réglages, jamais en alerte modale par-dessus l'accueil.

**4. Pas de rouge.** Règle fondatrice de la v1. Le liseré de la bulle est en `Theme.accent` (bordeaux), pas en rouge. Seule la **pastille** de nouveauté est rouge, parce que c'est la convention iOS d'un badge et qu'elle ne porte aucun jugement sur l'utilisateur.

**5. `TabView(.page)` garde les pages voisines vivantes.** Leçon de la v1.5. Si un carrousel apparaît dans ce lot, prévoir le démontage par `isCurrent`. Le profil du duo, tel que spécifié, n'en a pas besoin.

**6. Reduce Motion coupe le battement du cœur.** Comme les micro-gestes de Nivelito depuis la v1.2. Le liseré, lui, reste : c'est le porteur de l'information, l'animation n'est qu'un renfort.

**Commandes de test :**
```bash
cd NivelCore && swift test
xcodegen generate
xcodebuild -project Nivel.xcodeproj -scheme Nivel \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' test
```

## Task 1 : `DuoService`, l'état observable

**Fichiers :** créer `App/Services/DuoService.swift`, `NivelTests/DuoServiceTests.swift`

- [ ] **Étape 1 : écrire les tests des décisions pures**

Le service parle à CloudKit, donc **seules ses décisions se testent**. Les extraire en statiques pures, comme `HomeView.bubbleDecision` l'a été en v1 :

```swift
/// Le premier `DuoMember` écrit gagne (spec §3.6). Deux personnes peuvent accepter
/// le partage avant que le lien ne se referme ; on ne veut ni trancher au hasard,
/// ni afficher un troisième larron.
func testLePremierMembreEcritGagne() {
    let a = membre(id: "A", creation: Date(timeIntervalSince1970: 100))
    let b = membre(id: "B", creation: Date(timeIntervalSince1970: 200))
    XCTAssertEqual(DuoService.partner(among: [b, a], excluding: "MOI")?.memberID, "A")
}

/// Mon propre instantané n'est jamais mon partenaire, même s'il est le plus ancien.
func testMonPropreInstantaneNEstJamaisLePartenaire() {
    let moi = membre(id: "MOI", creation: Date(timeIntervalSince1970: 50))
    let autre = membre(id: "A", creation: Date(timeIntervalSince1970: 100))
    XCTAssertEqual(DuoService.partner(among: [moi, autre], excluding: "MOI")?.memberID, "A")
}

/// Zone rejointe mais personne d'autre encore : ce n'est pas une erreur, c'est
/// l'instant entre l'acceptation et la première écriture de l'autre.
func testSeulDansLaZoneNEstPasUneErreur() {
    let moi = membre(id: "MOI", creation: Date(timeIntervalSince1970: 50))
    XCTAssertNil(DuoService.partner(among: [moi], excluding: "MOI"))
}

/// Le lien se referme dès qu'il y a deux membres (spec §3.6).
func testLePartageSeFermeDesQuUnSecondMembreApparait() {
    XCTAssertFalse(DuoService.shouldKeepShareOpen(memberCount: 2))
    XCTAssertTrue(DuoService.shouldKeepShareOpen(memberCount: 1))
}

/// Les cœurs qui me visent, et seulement eux. Le filtrage se fait côté client sur
/// `giverID` : on ne s'en remet pas au fait que CloudKit épargne l'appareil d'origine.
func testSeulsLesCoeursDesAutresQuiMeVisentComptent() {
    let miens = like(giver: "MOI", owner: "MOI", event: "E1")
    let sienSurMoi = like(giver: "TOI", owner: "MOI", event: "E2")
    let sienSurLui = like(giver: "MOI", owner: "TOI", event: "E3")
    XCTAssertEqual(
        DuoService.incomingLikes(from: [miens, sienSurMoi, sienSurLui], me: "MOI").map(\.eventID),
        ["E2"])
}
```

## Task 4 : l'abonnement et la notification locale

/// La ligne de fraîcheur. Elle n'est pas décorative : les données PEUVENT être en
/// retard, et il vaut mieux le dire que laisser croire à un chiffre juste.
func testLaLigneDeFraicheurSeLitEnFrancais() {
    let base = Date(timeIntervalSince1970: 10_000)
    XCTAssertEqual(DuoProfileView.freshness(generatedAt: base,
                                            now: base.addingTimeInterval(240)),
                   "mis à jour il y a 4 min")
    XCTAssertEqual(DuoProfileView.freshness(generatedAt: base,
                                            now: base.addingTimeInterval(20)),
                   "mis à jour à l'instant")
}

/// Journée vide : on le dit sans reproche. Aucun « seulement », aucun « déjà »
/// (règle zéro culpabilisation, qui vaut dans ce sens-là aussi).
func testLeFilVideParleSansReproche() {
    let texte = DuoProfileView.emptyFeedText(partner: "Marion")
    XCTAssertEqual(texte, "Marion n'a rien noté pour l'instant")
    for interdit in ["seulement", "déjà", "encore rien", "aucun effort"] {
        XCTAssertFalse(texte.lowercased().contains(interdit))
    }
}

/// Un instantané d'hier ne doit pas s'afficher comme la journée d'aujourd'hui : à

func testUnInstantaneDHierNAffichePasSonFil() {

    XCTAssertFalse(DuoProfileView.isStale(dayKey: "2026-08-16", today: "2026-08-16"))
}

## Vérification finale du lot A2

**Automatique :**
- [ ] `cd NivelCore && swift test` : verte.
- [ ] `xcodebuild ... test` : cible entière verte.
- [ ] Sans duo appairé, l'accueil est **pixel pour pixel** celui de la 1.14, hormis le resserrement de l'en-tête.

**Sur les deux iPhones — rien de ce qui suit n'est couvert par un test, et c'est la seule façon de le savoir :**
- [ ] appairage complet par QR, de bout en bout ;
- [ ] le lien refuse un troisième arrivant après la fermeture du partage ;
- [ ] un cœur envoyé arrive en notification, app **en arrière-plan** ;
- [ ] app **tuée depuis le sélecteur** : aucune notification, et la bulle bordée rattrape à l'ouverture — c'est le comportement attendu, pas un défaut ;
- [ ] bascule de minuit : le fil du partenaire se vide sans qu'on ouvre l'app ;
- [ ] mode avion : la page affiche le cache et sa ligne de fraîcheur, sans écran vide ;
- [ ] caméra refusée : le champ « coller un lien » prend le relais ;
- [ ] désappairage des deux côtés, puis réappairage ;
- [ ] un iPhone sans compte iCloud : la section Duo l'explique, rien ne plante.
