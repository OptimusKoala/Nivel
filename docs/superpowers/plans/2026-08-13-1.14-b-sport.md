# Nivel 1.14 — Lot B : Sport — Plan d'implémentation

> **Pour les agents :** SOUS-COMPÉTENCE REQUISE — utiliser `superpowers:subagent-driven-development` (recommandé) ou `superpowers:executing-plans` pour exécuter ce plan tâche par tâche.

**But :** dix activités intenses dans une section « Ça pousse », et un programme muscu maison de cinq séances derrière un interrupteur par téléphone.

**Architecture :** `Activity` gagne deux champs — `intensity`, qui range la nouvelle section, et `stepsBased`, que le lot C lira pour ne pas compter une marche deux fois. Le programme muscu est le miroir de `PosturePlanSettings`, **à une différence près** : pas de catalogue d'exercices séparé, ses séances pointent vers les activités « Ça pousse » du catalogue commun. Sa rotation reste cloisonnée dans `muscu-sessions.json`, sans quoi la séance du jour de tout le monde changerait.

**Pile :** Swift 6, SwiftUI, SwiftData, XCTest, `UserDefaults` pour l'interrupteur par appareil.

**Spec :** `docs/superpowers/specs/2026-08-13-nivel-1.14-design.md` §4. Tableaux d'activités, de séances et d'illustrations : **y aller les lire, ne pas les recopier**.

**Dépendance :** aucune sur le lot A. Le lot C dépend de **Task 1** de ce plan (`stepsBased`).

```swift
/// Le découpage de l'onglet Sport (spec v1.14 §4.3), en un seul endroit : deux
/// vues affichent les mêmes activités (`SportView` et `ActivityPickerSheet`) et
/// elles ne doivent pas pouvoir diverger.
///
/// L'ordre des sections n'est pas décoratif : le doux reste le chemin par défaut,
/// l'intense est un pas qu'on descend chercher.
public enum ActivityCatalogSections {
    public static func gentleHome(_ activities: [Activity]) -> [Activity] {
        activities.filter { $0.intensity == .gentle && $0.location != .outdoor }
    }
    public static func gentleOutdoor(_ activities: [Activity]) -> [Activity] {
        activities.filter { $0.intensity == .gentle && $0.location == .outdoor }
    }
    public static func strong(_ activities: [Activity]) -> [Activity] {
        activities.filter { $0.intensity == .strong }
    }
}
```

```swift
// Programme muscu maison (spec v1.14 §4.4) : catalogue de SÉANCES séparé, avec sa
// propre rotation.
//
// Le cloisonnement du fichier n'est pas un rangement : verser ces cinq séances dans
// sessions.json ferait passer la rotation de la séance du jour de 11 à 16 entrées,
// donc changerait la séance vue chaque jour par tout le monde. La spec sport l'interdit.
//
// Différence avec PostureCatalog : pas de catalogue d'exercices propre. Les étapes
// pointent vers les activités « Ça pousse » du catalogue commun, déjà visibles par
// tous — dupliquer des exercices identiques serait deux vérités pour un même mouvement.

import Foundation

public struct MuscuCatalog: Sendable {
    public let sessions: [ActivitySession]

    public static func load() throws -> MuscuCatalog {
        MuscuCatalog(sessions: try Catalogs.muscuSessions())
    }

    /// Repli sans crash quand le JSON est corrompu, comme les six autres catalogues.
    public static let empty = MuscuCatalog(sessions: [])

    /// Même rotation générique que la séance du jour, appliquée au pool muscu.
    public func session(for date: Date, calendar: Calendar) -> ActivitySession? {
        DailySessionPicker.session(for: date, sessions: sessions, calendar: calendar)
    }

    public func kcal(_ session: ActivitySession, activitiesByID: [String: Activity]) -> Int {
        session.estimatedKcal(activitiesByID: activitiesByID)
    }
}
```

Dans `Catalogs.swift` :

```swift
/// Séances muscu (spec v1.14 §4.4) : fichier SÉPARÉ de sessions.json, pour ne
/// jamais entrer dans la rotation de la séance du jour.
public static func muscuSessions() throws -> [ActivitySession] { try load("muscu-sessions") }
```

`muscu-sessions.json` : les cinq séances de la **spec §4.4**, au format exact de `sessions.json` (`tempo` sur chaque étape, `segments` quand les séries sont explicites).
