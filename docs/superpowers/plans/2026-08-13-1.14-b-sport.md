# Nivel 1.14 — Lot B : Sport — Plan d'implémentation

> **Pour les agents :** SOUS-COMPÉTENCE REQUISE — utiliser `superpowers:subagent-driven-development` (recommandé) ou `superpowers:executing-plans` pour exécuter ce plan tâche par tâche.

**But :** dix activités intenses dans une section « Ça pousse », et un programme muscu maison de cinq séances derrière un interrupteur par téléphone.

**Architecture :** `Activity` gagne deux champs — `intensity`, qui range la nouvelle section, et `stepsBased`, que le lot C lira pour ne pas compter une marche deux fois. Le programme muscu est le miroir de `PosturePlanSettings`, **à une différence près** : pas de catalogue d'exercices séparé, ses séances pointent vers le catalogue commun. Sa rotation reste cloisonnée dans `muscu-sessions.json`, sans quoi la séance du jour de tout le monde changerait.

**Pile :** Swift 6, SwiftUI, SwiftData, XCTest, `UserDefaults` pour l'interrupteur par appareil.

**Spec :** `docs/superpowers/specs/2026-08-13-nivel-1.14-design.md` §4. Tableaux d'activités, de séances et d'illustrations : **y aller les lire, ne pas les recopier**.

**Dépendance :** aucune sur le lot A. Le lot C dépend de la **Task 1** de ce plan (`stepsBased`) et de sa **Task 5** (`XPAction.muscuSessionDone`).

## ⚠️ Trois règles de ce dépôt, à ne pas redécouvrir en cours de route

**1. Le projet Xcode est généré.** `Nivel.xcodeproj` n'a aucun groupe synchronisé (`PBXFileSystemSynchronizedRootGroup` : 0) : chaque fichier est référencé explicitement. **Tout fichier créé exige `xcodegen generate`** avant le moindre `xcodebuild`, sinon il n'est pas compilé et l'erreur observée n'est pas celle qu'on attend (« classe de test introuvable », pas « symbole inconnu »). Ce plan crée quatre fichiers ; la commande apparaît à chaque fois.

**2. Trois `switch` sont exhaustifs et sans `default`.** Ajouter `ActivityKind.muscu` **casse la compilation** de `GameService+Sport.swift:47-53` (`logSport`) et de `SportView.swift:133-146` (`doneRow`). Ajouter `XPAction.muscuSessionDone` casse `XPEngine.swift:16-29`. Ce n'est pas un défaut : c'est le compilateur qui refuse qu'on oublie un cas. Les trois se traitent **dans la même tâche** que l'ajout du cas.

**3. Un rappel exige son contexte de message.** `MessageContext` est un enum fermé, `MessageBank.load` lève `assertionFailure` sur une clé absente, et `MessageBankTests` exige **≥ 12 messages par contexte**. Un nouveau rappel = un nouveau contexte = douze textes à écrire.

> **Noms de test en français.** Les extraits de test de ce plan portent des noms anglais (`testDessertCategoryExists`) : c'est une facilité de rédaction, pas une consigne. Les suites du dépôt sont en français (`testPasDeDoublonDId`, `testUniteEtPoidsVontEnsemble`) — **traduire chaque nom de test au moment de l'écrire**. Le corps et les assertions, eux, se reprennent tels quels.

/// Le découpage de l'onglet Sport (spec v1.14 §4.3), en un seul endroit : deux vues
/// affichent les mêmes sections (`SportView` et `ActivityPickerSheet`) et elles ne
/// doivent pas pouvoir diverger. Pas seulement sur l'appartenance : le libellé,
/// l'icône, l'ordre et la simple PRÉSENCE d'une section viennent d'ici aussi.
public enum SportSection: String, CaseIterable, Sendable {
    case gentleHome, gentleOutdoor, strong

    /// Ordre d'affichage (spec v1.14 §4.3) : le doux d'abord, il reste le chemin par
    /// défaut ; l'intense en dernier, un pas qu'on descend chercher. Explicite et non
    /// déduit de `allCases` : un cas inséré au milieu de l'enum réordonnerait l'écran
    /// sans que personne ne le demande. Un test vérifie qu'aucune section n'y manque.
    public static let displayOrder: [SportSection] = [.gentleHome, .gentleOutdoor, .strong]

    public var frLabel: String {
        switch self {
        case .gentleHome: "À la maison"
        case .gentleOutdoor: "Dehors"
        case .strong: "Ça pousse"
        }
    }

    /// Glyphe cozy de l'en-tête. Un test de la cible app le résout contre les assets
    /// réels : une faute de frappe ici n'afficherait rien du tout, sans un bruit.
    public var icon: String {
        switch self {
        case .gentleHome: "tab_home"
        case .gentleOutdoor: "icon_tree"
        case .strong: "icon_flame"
        }
    }

    /// Les activités de la section. Les trois partitionnent le catalogue : `.both`
    /// (les escaliers) n'est pas `.outdoor`, donc elle part avec « À la maison » —
    /// une fois, et une seule.
    public func activities(in activities: [Activity]) -> [Activity] {
        switch self {
        case .gentleHome: activities.filter { $0.intensity == .gentle && $0.location != .outdoor }
        case .gentleOutdoor: activities.filter { $0.intensity == .gentle && $0.location == .outdoor }
        case .strong: activities.filter { $0.intensity == .strong }
        }
    }
}

// NivelCore/Tests/NivelCoreTests/MuscuPlanTests.swift
// Programme muscu maison (spec v1.14 §4.4) : catalogue de SÉANCES cloisonné,
// exercices pris dans le catalogue commun, rotation propre.
import XCTest
@testable import NivelCore

final class MuscuPlanTests: XCTestCase {
    private func parisCalendar() -> Calendar {
        var calendar = Calendar(identifier: .gregorian)
        calendar.timeZone = TimeZone(identifier: "Europe/Paris")!
        return calendar
    }

    func testSessionsLoadAndStepsResolveInTheSharedCatalogue() throws {
        let catalog = try MuscuCatalog.load()
        XCTAssertEqual(catalog.sessions.count, 5)
        XCTAssertEqual(Set(catalog.sessions.map(\.id)).count, 5)
        // Différence assumée avec la posture : PAS de catalogue d'exercices séparé.
        let shared = Set(try Catalogs.activities().map(\.id))
        for session in catalog.sessions {
            XCTAssertFalse(session.steps.isEmpty, session.id)
            for step in session.steps {
                XCTAssertTrue(shared.contains(step.activityID),
                              "\(session.id) référence \(step.activityID), absent du catalogue commun")
                XCTAssertGreaterThan(step.minutes, 0, "\(session.id)/\(step.activityID)")
            }
        }
    }

    /// LE test qui protège la spec sport : verser ces séances dans sessions.json
    /// ferait passer la rotation de 11 à 16 entrées et changerait la séance vue
    /// chaque jour par les DEUX téléphones.
    func testMuscuDoesNotTouchTheSharedRotation() throws {
        let shared = try Catalogs.sessions()
        XCTAssertEqual(shared.count, 11)
        let muscuIDs = Set(try MuscuCatalog.load().sessions.map(\.id))
        XCTAssertTrue(Set(shared.map(\.id)).isDisjoint(with: muscuIDs))
    }

    /// La rotation est déterministe : même jour, même séance, à chaque ouverture.
    func testRotationIsDeterministic() throws {
        let catalog = try MuscuCatalog.load()

### Trois décisions de design que le plan tranche

**1. `XPAction.muscuSessionDone` appartient à ce lot**, avec son barème (40 XP, plafond 1/jour). `XPEngine.award` est un `switch` exhaustif sans `default` : un cas ajouté sans valeur ne compile pas. Le lot C ne fera que les quêtes.

**2. Le drapeau de rappel se généralise.** `ReminderDefinition.requiresPosturePlan: Bool` et les deux portes `visibleReminders(planEnabled:)` / `ReminderPlanner.planned(…planEnabled:)` ne connaissent **qu'un** programme. Ajouter un second booléen doublerait chaque signature et laisserait la porte ouverte à un troisième. On remplace donc par :

```swift
/// Programme dont un rappel dépend (spec v1.11 §3, v1.14 §4.4). `nil` = rappel
/// ordinaire, toujours visible.
///
/// Généralisé depuis le booléen `requiresPosturePlan` de la v1.11 : la 1.14
/// apporte un second programme, et deux booléens auraient dédoublé chaque
/// signature. La règle, elle, ne change pas d'un iota — un rappel de programme
/// ne doit jamais apparaître dans les Réglages tant que son programme est
/// éteint, sinon (a) une ligne visible en plus casse la promesse « rien ne
/// change chez toi », et (b) n'importe qui peut l'allumer sans avoir jamais vu
/// le programme, et le laisser sonner en silence.
public enum ReminderPlan: String, Codable, Sendable { case posture, muscu }

public let requiresPlan: ReminderPlan?
```

Les deux portes prennent `enabledPlans: Set<ReminderPlan>` et filtrent sur `requiresPlan.map(enabledPlans.contains) ?? true`.

**3. Le rappel muscu a son propre contexte de message.** Réutiliser `.postureReminder` ferait dire à Nivelito un texte de posture pour une séance de pompes. On ajoute `.muscuReminder` **et ses douze textes** dans `messages.json` — `MessageBankTests` l'exige, et `MessageBank.load` lève `assertionFailure` sur une clé absente.
